# SSHDesk project

- Build a Windows-first, local-only SSH/Bastion/Tunnel desktop agent in Go. Embed HTML, CSS, JavaScript and xterm.js; no Node/React application or runtime CDN.
- Bind HTTP and local tunnels only to 127.0.0.1. Validate HTTP Host, Origin, CSRF tokens and WebSocket Origin. Verify SSH server keys using known_hosts or explicitly verified SHA256 fingerprints.
- Exception: an explicitly enabled, separate team-download listener uses IPv4 TCP 9877 for same-subnet peers. It exposes only a landing page, executable and configuration export, never management APIs, terminals or key contents. Keep the management listener and forwarded ports on loopback. Windows inbound rules must restrict port 9877 to LocalSubnet. Show Team sharing below Settings; default sharing off, with optional -share startup flag.
- User-authorized exception for team installers: the owner may explicitly select private keys and prepare a local-only executable bundle containing those keys plus dependent hosts/tunnels/web links. Require explicit selection of any Jump Host dependency keys. Never publish such bundles to GitHub or expose key bytes through JSON/config APIs. On first launch, install keys under a protected per-user data folder and merge configuration without overwriting existing records or auto-connecting. Strip old payloads when redistributing an executable, clear prepared bundles on sharing stop/exit, and publish only clean compiled executables in public releases. Show the preferred route's IP first; hide additional interface addresses in a disclosure.
- Store private-key file paths only in the database, never passwords, key contents or passphrases. Do not modify the user's SSH config or known_hosts automatically.
- Key registration supports manual runtime paths and browser file selection on Windows/macOS, including WSL/Docker servers. Explicitly selected keys are uploaded only on Save to a protected uploaded-keys folder beside the database, with random filenames, a 1 MiB limit, format validation and rollback on failure. Never expose key bytes in responses, exports, logs, Git or public releases; retain Host/Origin/CSRF protections. Cancellation performs no writes.
- Keep OS-specific browser launching and data directory selection in internal/platform. Use interfaces for SSH and tunnel tests.
- Test against isolated local SSH servers; do not connect to real company hosts without an explicit request. Run go test ./..., go vet ./..., Linux race tests and Windows build/smoke checks for connection changes.
- Keep sidebar order: Dashboard, Hosts, Terminal, Tunnels, Keys, Settings, then Team sharing. Services is merged into Tunnels; manage optional named web URLs in the tunnel editor and open them from tunnel rows. Preserve all legacy service records and backup compatibility. Saving must never connect; opening a web link starts/checks its tunnel. Tunnel deletion also removes its web links. Do not add SFTP, logs or Docker management.
- Database migrations use ordinary indexes; integrity and reference validation run under the store mutation lock, following the parent workspace schema policy.
- Configuration and SSH files stay local. Export/import must never include key bytes, passwords, SSH file contents or history; exports contain sensitive connection metadata and must be excluded from Git. Import previews additions, preserves conflicting existing records, applies atomically, and never starts connections.
- Before publishing to the project Git remote, inspect the staged file list and scan for credentials, private keys, local databases, exported configurations, internal endpoints and personal paths. Publish source and sanitized documentation only.
- For future executable releases, build and verify the Windows binary, attach it as `sshdesk.exe` to a versioned GitHub Release, and keep the prominent README download button and getting-started link pointed at `https://github.com/qmdch1/Gatedock/releases/latest/download/sshdesk.exe`. Do not commit executables to Git or create releases for documentation-only edits. Release assets must exclude local configuration, databases, private keys and personal paths.
- Keep README product-focused: lead with an overview explaining the inconvenience of switching tools during internal-network development, then features and configuration-file sharing with teammates. Omit cosmetic implementation notes and local development-session details; distinguish shared configuration from private keys and access permissions.
- Keep README team-sharing instructions short and directly executable: owner steps and separate Windows/Mac recipient steps. Collapse troubleshooting details and use actual configured UI screenshots with fully synthetic data; never expose real project names, addresses or key paths.
- At startup, automatically import new aliases from the saved SSH config path (Windows default: %USERPROFILE%\.ssh\config). Preserve existing records and source files, skip invalid aliases/dependencies, report results in Settings, and never auto-connect. Support -no-auto-import for isolated runs.
- Show a brief success toast after a user-triggered Dashboard Refresh completes. Background polling stays silent; failed requests show only the error notification.
- Settings SSH Import preview must have a Close button that clears preview content, selected aliases and the preview path, and returns focus to the preview trigger.
- Team downloads support macOS through a ZIP containing native OpenSSH config, setup script and copyable host/tunnel commands, plus separate config/guide text downloads. Include private keys only from an explicitly prepared selection. Preserve ~/.ssh/config and known_hosts, use isolated ssh -F configs, retain host-key checks, and do not connect during installation. Distinguish this from a macOS GUI app.
- Keep Configuration backup compact: selected filename field, file selection, export, preview and import configuration controls. Preserve local SSH config/known_hosts settings and require successful preview before applying.
- Limit the backup filename field to 300px and place Preview / Import configuration on a separate row below the file selection and export controls.
- Default to a high-contrast light management UI: white panels/navigation/forms, pale page background, dark readable text and clear environment/status colors. Only the interactive terminal canvas remains dark. This supersedes the original dark-mode default.

- Team recipients installed from a newly prepared Windows bundle subscribe to the originating master. Poll signed, nonce-bound, key-scoped snapshots every 30 seconds while sharing is enabled; pin the source signing key and reject redirects, proxies and non-local source URLs. Add/update only managed configuration, preserve local key paths and personal records, never propagate deletion, and mark absent shared records as retained/missing. Keep running connections intact. Persist provenance and signing identity outside exports; expose only read-only scoped feeds on the sharing listener. Private-key additions/rotation require a fresh explicitly prepared installer. Plain JSON and macOS text bundles remain manual imports.

- Docker uses bridge networking with host-side loopback port mappings: 9876 for management and 18080-18089 for default tunnels. The explicit Linux-only -container-network flag binds management/tunnel listeners to container interfaces while retaining loopback Host/Origin validation and stored tunnel addresses. Never expose these ports on host 0.0.0.0. Do not require Docker Desktop host networking; verify the actual host browser path, not just container-local health.

- Team-sharing key selection defaults to all keys when no prepared selection exists; preserve a prepared subset and in-page edits, including clearing all. Provide select-all/clear-all controls and a selected count. Display a prominent green sharing-enabled banner above the panel, updated from actual server status. Selection alone must not prepare or publish key bundles.

- Settings config/known_hosts file selection is browser-based across OSes. Copy only on Save into protected uploaded-settings beside the DB, with a combined 1 MiB limit, validation and rollback; do not overwrite originals. Ignore uploaded-settings in Git. Team sharing uses one publish action to prepare the selected keys and start sharing; no selection publishes without private keys. Keep copy-address and stop controls prominent; open key selection and connection-status sections by default; keep advanced subscription controls collapsed. Do not publish merely on selection.

- Keep management text readable: 15px base text, 14px forms/table text/help/small buttons, and 16px checkbox/key labels with 18px checkboxes and comfortable row spacing. Reserve smaller text for decorative branding or compact badges; inspect wrapping at desktop and narrow widths after typography changes.
